# Spec Delta

## Purpose

Regions (GDD-6.4) group locations so distribution rules can express GDD-3.3's interdependence guarantee: no region can supply every raw resource. Location property vectors and source slots (GDD-6.5) may be authored fixed or generated by a seeded, deterministic distribution rule (CONT-6.18).

## ADDED Requirements

### Requirement: Region definitions and location membership
The content layer SHALL accept a `regions` collection of `{ id, tags? }` definitions, SHALL accept an optional `region` field on location templates and world locations, and SHALL resolve the effective region (world-location override, else the template's) to the region definition handle on the location plan. An unresolvable region SHALL report `unresolved_reference`.

Source: GDD-6.4, CONT-6.18, CONT-6.6

#### Scenario: A location joins a region
- **WHEN** content defines region `test.region.alpha`, a template `test.location.a` with `region: test.region.alpha`, and a world location for that template with no `region` override
- **THEN** the location plan's region resolves to the `test.region.alpha` handle and instantiation writes it into the location's `region` field

#### Scenario: A world location overrides the template region
- **WHEN** a world location declares `region: test.region.beta` for a template whose `region` is `test.region.alpha`
- **THEN** the location plan's region is the `test.region.beta` handle

#### Scenario: An unknown region is reported
- **WHEN** a world location declares `region: test.region.missing`
- **THEN** the content load reports `unresolved_reference` expecting a `region` definition

### Requirement: Distribution rule schema
The content layer SHALL accept a `distribution_rules` collection of `{ id, regions, disjoint: { properties, source_slot_types }, generation: { mode, seed_stream? } }` where `regions` is a list of region IDs, `properties` is a list of glob patterns, `source_slot_types` is a boolean, `mode` is `fixed` or `seeded`, and `seed_stream` defaults to `world_generation`. A rule with fewer than two regions, duplicate regions, or an empty disjoint specification SHALL report `invalid_distribution_rule`; a `regions` entry that does not resolve SHALL report `unresolved_reference`.

Source: CONT-6.18

#### Scenario: A well-formed rule validates
- **WHEN** a rule lists regions `test.region.alpha` and `test.region.beta` with `disjoint: { properties: [test.property.suitability_*], source_slot_types: true }` and `generation: { mode: fixed }`
- **THEN** the content load reports no diagnostics for the rule

#### Scenario: A single-region rule is rejected
- **WHEN** a rule lists only region `test.region.alpha`
- **THEN** the content load reports `invalid_distribution_rule`

### Requirement: Disjoint validation of authored attributes
For each distribution rule, every matched property name (a name authored on a location template or world location of the catalogue that matches at least one of the rule's `properties` globs) and every source slot type authored on a location of one of the rule's regions SHALL be supplied by at most one of the rule's regions, where a region supplies a name when a location of that region authors a non-zero value or slot count. A violation SHALL report `distribution_not_disjoint`.

Source: GDD-3.3, GDD-6.4, CONT-6.18

#### Scenario: Two regions supplying the same property violate the rule
- **WHEN** regions `alpha` and `beta` are joined by a disjoint rule over `test.property.suitability_*`, and a location of each region authors `test.property.suitability.c: 1000`
- **THEN** the content load reports `distribution_not_disjoint`

#### Scenario: Disjoint authored attributes pass
- **WHEN** the locations of `alpha` author only `test.property.suitability.c` and the locations of `beta` author only `test.property.suitability.d`, joined by the same rule
- **THEN** the content load reports no diagnostics

#### Scenario: A zero value supplies nothing
- **WHEN** a location of region `alpha` authors `test.property.suitability.c: 0` and a location of region `beta` authors `test.property.suitability.c: 500`
- **THEN** the content load reports no diagnostics

### Requirement: Seeded generation of property vectors and slots
When a location's effective region belongs to a rule with `generation.mode: seeded`, world instantiation SHALL assign each matched property name and each slot type authored anywhere in the catalogue to exactly one of the rule's regions: a name authored with a non-zero value or count on a location of one of the rule's regions SHALL be owned by that region, and every remaining name SHALL be drawn with `nextInt(createStream(seed, '<seed_stream>.<name>'), region_count)` iterated in ascending name order. Instantiation SHALL then complete the location's effective attributes: authored values win, and a matched name the location does not author SHALL take the value `1000` in the owning region and `0` elsewhere; a location with no authored `source_slots` SHALL receive a count of `1` for each slot type its region owns, in ascending type order. The same world seed SHALL produce identical attributes, and generation SHALL not let two rule regions supply the same matched name.

Source: GDD-3.3, GDD-6.5, CONT-6.18, TDS-15

#### Scenario: A seeded rule fills the region's property vector
- **WHEN** a seeded rule over property `test.property.suitability_c` covers regions `alpha` and `beta`, and a location of `alpha` authors no properties
- **THEN** the location's effective vector contains `test.property.suitability_c` with value `1000` or `0`, and the location of `beta` receives the complementary value

#### Scenario: Authored values are not overwritten
- **WHEN** a location of the owning region authors `test.property.suitability_c: 400` under a seeded rule
- **THEN** its effective value stays `400`

#### Scenario: An authored name stays with its authoring region
- **WHEN** a location of region `alpha` authors `test.property.suitability_c: 1000` under a seeded rule and the rule covers regions `alpha` and `beta`
- **THEN** every location of `beta` receives `0` for `test.property.suitability_c`

#### Scenario: Generation is deterministic per seed
- **WHEN** the same content is instantiated twice with seed `[7, 11]`
- **THEN** both runs produce identical property vectors and source slots, and each matched name is owned by exactly one region

### Requirement: Region in the location projection
The location entry of the per-actor snapshot SHALL carry the location's region string ID in `properties.region` when the location has a region, and the location-summary read model SHALL populate its `region` field the same way; locations without a region SHALL omit both fields. The snapshot and read-model codecs SHALL decode the fields.

Source: PIC-9.1, PIC-10.2

#### Scenario: A regionful location projects its region
- **WHEN** the projection is built for a location whose region is `test.region.alpha`
- **THEN** the location DTO's `properties.region` and the summary's `region` are `test.region.alpha`

#### Scenario: A regionless location omits the field
- **WHEN** the projection is built for a location with no region
- **THEN** the location DTO's `properties` carry no `region` key
