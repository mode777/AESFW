# Proposal

## Why

Roadmap 08, M11a item 11.4a. The deployed client is still the planner dashboard the `redesign-reference-game-client` change replaced in `docs/07`: raw string IDs (the presentation package is never loaded), a button list instead of the §11 layout, and a broken content bundle after 11.1's file split. This row builds the game-HUD shell everything else in M11a mounts into, and it retires the first leg of **R-08** (the game looks and reads like a game, not a tool).

Depends on: `add-client-exchange-view` 9.5 (archived 2026-10-25). Per 08 §11 (M10 "Next") this row runs in parallel with `add-reference-content-prototype` (11.1); it must be archived before 11.4b. Order within M11: second overall (parallel with 11.1), before all other client rows.

## What Changes

- The dashboard shell (top bar, drawer tab strip, notice strip) is replaced by the fixed full-bleed HUD frame of 07 §11: a resource bar (top left), a location banner (top centre), a news-rail slot (left, populated by 11.4f), a minimap + population slot (bottom left, populated by 11.4b), an action bar (bottom centre), and a context-panel slot (bottom right, populated by 11.4c/11.4d).
- The client loads `ref.tier.presentation` (names, descriptions, categories, formatting) through a build-time conversion of the YAML package into client data; fallback shapes and key labels remain for absent mappings (07 §14.4).
- The existing drawer views (economy, planning, logistics, exchange, population/progression, tables) are re-hosted unchanged as provisional floating windows opened from the action bar, so the client stays fully usable until 11.4e replaces them with the §12.4 window set.
- Table mode and the debug overlay are retained (07 §9 principle 7, §12.5); client-local settings move to the `aesfw-ref.client.v2` storage key (07 §14.5).
- The content bundle is fixed for 11.1's split package layout and grows to carry both packages.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `reference/client`: the shell requirements change — the top bar becomes the action bar, the balance display becomes the resource bar of the viewed location, a location banner is added, presentation data is loaded, and view state gains camera, pinned resources, open windows, and theme.

## Impact

- **Packages:** `reference/client-web` only (`main.ts` composition, `views/`, `store/`, `i18n/`, build scripts). No framework package, phase, store kind, command, event, error code, or diagnostic code changes; the client still imports only `@aesfw/protocol` and `@aesfw/host-web/client`.
- **Protocol:** no change; presentation data is bundled client data because a headless host never loads presentation packages (PIC-5).
- **Tooling:** a build-time script converts `ref.tier.presentation/*.yaml` into a generated client data module (checked in, regenerated by task, diffed by CI).
- **Goldens:** none.

## Out of scope

- `add-reference-content-prototype` (11.1) owns the presentation package contents.
- `add-client-world-canvas` (11.4b): the canvas, camera, layout, minimap, fog, lanes.
- `add-client-construction-flow` (11.4c) and `add-client-context-panels` (11.4d): the context panel's build menu and info panels.
- `add-client-windows-routes-and-trade` (11.4e): the final §12.4 window set, explore/establish from the canvas.
- `add-client-news-and-milestones` (11.4f) and `add-client-polish-and-accessibility` (11.4): news rail content, hints, milestones, palette, dark theme, axe.
